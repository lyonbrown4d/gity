# 前后端共享国际化

`crates/gity-i18n/locales` 是中英文文案的共同来源。Rust Web 和服务端均依赖此 crate，构建时由 `rust-i18n` 嵌入资产；不需要浏览器临时下载远程语言包。

每条资产同时维护 `en`、`zh`。现有 UI 英文短语继续作为键，以兼容迁移前调用。新增消息也须在共享目录登记；不要在服务端和 Web 分别维护同一文案。

```rust
let message = gity_i18n::translate(
    "Type {path} to confirm deletion.",
    "zh-CN",
    &[("path", "team/project")],
);
```

参数使用库的命名占位符处理，应用接口保留 `{path}` 模板兼容性。测试检查键重复、两种语言完整性、占位符一致性、插值内容和并发语言隔离。

## Web

语言选择保存在浏览器偏好中。每次 JSON 或上传请求重新读取偏好并发送 `Accept-Language`，用户切换后不需要重新登录。

## 服务端

服务端按 `Accept-Language` 的质量权重和顺序选择 `zh` 或 `en`，中文地区标签如 `zh-CN`、`zh-TW` 归一到 `zh`；不支持的语言回退为英文。

请求语言保存在 Tokio task-local 上下文，禁止调用全局 `set_locale`。错误响应通过共享目录翻译，响应附带 `Content-Language` 和 `Vary: Accept-Language`。

状态码、机器字段和业务标识不随语言变化。已收录的固定错误提示提供翻译；未知的动态内容保留原文。500 响应只返回统一提示，内部错误通过服务端日志排查。

## 修改语言包

1. 同时补齐 `en` 和 `zh`，避免混入业务标识或秘密值。
2. 每个手写资产文件不超过 300 行，按功能拆分。
3. 新建文件时同步维护测试用 `src/assets.rs` 清单。
4. 运行 `cargo test -p gity-i18n -p gity-core` 和服务端请求语言回归。
5. 检查窄屏、按钮和表格中的中文换行。
